Declaring a Variable (Simplified)

你可以将你的计算机想象成包含大量用于存储信息的内存位，每个位都有一个唯一的地址。现代计算机可以提供数十亿个这样的位。

当你声明一个特定类型的变量时，Java 会找到一个恰好能容纳该类型数据的连续位块。例如，如果你声明一个 int 类型，你会得到一个 32 位的块；如果你声明一个 byte 类型，你会得到一个 8 位的块。每种数据类型在 Java 中占用的位数都不同。这个确切的位数对于我们这门课来说并不是特别重要。

为了有一个方便的比喻，我们将其中一个这样的块称为“比特盒”。

除了分配内存外，Java 解释器还在一个内部表中创建一个条目，将每个变量名映射到该盒子中第一个比特的位置。

例如，如果你声明了 int x 和 double y ，那么 Java 可能会决定使用你计算机内存中的第 352 到 384 位来存储 x，第 20800 到 20864 位来存储 y。解释器随后会记录 int x 从第 352 位开始，y 从第 20800 位开始。例如，在执行了以下代码之后：

这一 Java 特性是一种权衡！将内存位置隐藏起来虽然让程序员失去了部分控制权，从而无法进行某些类型的优化，但它也避免了大量非常棘手的编程错误。在当今计算成本极低的时代，这种权衡通常是非常值得的。正如智慧的 Donald Knuth 曾经所说：“我们应该忘记那些小的效率优化，大约占 97%的时间：过早的优化是万恶之源。”

作为一个类比，你并不能直接控制自己的心跳。虽然这限制了你在某些情况下优化的能力，但也避免了像不小心把它关掉这样的愚蠢错误的可能性。（哈哈哈哈哈哈哈哈哈哈哈哈）

Get

虽然 size 方法可以让我们获取列表的大小，但我们没有简单的方法来获取列表的第 i 个元素。

练习：编写一个方法 get(int i) ，返回列表中的第 i 个元素。例如，如果 L 是 5 -> 10 -> 15，那么 L.get(0) 应该返回 5， L.get(1) 应该返回 10， L.get(2) 应该返回 15。对于无效的 i ，无论太大还是太小，你的代码可以有任意行为。

请注意，我们编写的方法需要线性时间！也就是说，如果你有一个长度为 1,000,000 的列表，那么获取最后一个元素将比在小列表中花费更长的时间。我们将在以后的课程中看到另一种实现列表的方法，以避免这个问题。

An Introduction to Asymptotic Analysis

之前，我们一直关注如何节省编写程序的时间。现在，我们将学习如何最有效地利用计算机的时间和内存。

我们可以从两个不同的角度来考虑编写高效程序的过程：

1.编程成本（截至当前日期的课程内容）
你的程序开发需要多长时间？
你的代码容易阅读或修改吗
你的代码可维护性如何？（非常重要——大部分成本来自维护和可扩展性，而非开发！）
2.执行成本（从本课程这一点开始的所有内容）
时间复杂度：你的程序执行需要多少时间？
空间复杂度：你的程序需要多少内存？
为了了解接下来要讨论的内容，考虑一个已排序的数组。我们的目标是确定列表中是否存在重复元素。

一种简单的方法是逐一比较每一对元素。在上述例子中，我们会将-3 与列表中的每个元素进行比较，然后是-1，接着是 2，以此类推。

一种更好的算法是利用列表的排序特性！我们不必逐一比较每一对元素，只需将每个元素与其相邻的元素进行比较即可。

我们可以看到，简单算法似乎比更好的算法做了更多不必要的、重复的工作。但它究竟多做了多少工作？我们如何量化程序的效率？本章将为您提供比较各种算法效率的正式技术和工具！

Runtime Characterization

我们希望能够表征先前看到的两种算法的运行时间。换句话说，我们希望提出某种代理指标，以传达每种算法的整体性能。

在表征运行时间时，我们有两个目标：

  • 它们应该是简单但数学上严谨的。
  • 如果一种算法比另一种算法更好，它们应该清楚地展示出一种算法优于另一种算法。

我们已经将朴素算法和更好的算法都转换成了 Java 代码。函数 dup1 对应于朴素算法，dup2 对应于更好的算法。

Technique 1

我们将考虑用于运行时特征化的第一种技术是使用客户端程序直接测量执行时间（以秒为单位）。

我们可以用几种方法来做这件事：

  • 使用物理秒表（不推荐）。
  • 使用 Unix 的内置 time 命令。
  • 使用普林斯顿标准库，它有一个 stopwatch 类。

使用这些方法中的任何一种（准确度因是否选择物理秒表路径而异）都会显示，随着输入规模的增加， dup1 需要更长时间完成，而 dup2 则相对以大致相同的速率完成。

看起来技术 1 在描述我们的运行时间方面效果完美！实验结果非常容易理解，而且实现起来也很简单。然而，它有一些严重的缺点，这使得我们不会用它来处理所有事情：

  • 运行完成可能需要很长时间。
  • 运行时间可能因机器、编译器、输入数据等因素而异。

由于这些原因，技术 1 在描述运行时间方面并不符合我们的目标。它很简单，但缺乏数学严谨性。此外，基于机器、编译器、输入等因素的差异意味着结果可能无法清晰地展示 dup1 和 dup2 之间的关系。

Technique 2A

与其实际计时算法运行所需的时间，我们可以转而计算每个算法完成的总操作次数！直观上，运行操作次数较少的算法会更为优越。我们可以将输入大小 N 固定为相同值，并比较两个算法运行的操作次数。

让我们将这种方法应用于输入大小为 N=10000 的 dup1 算法：

操作 i = 0 仅在函数调用的最开始运行一次。 j = i+1 更复杂——在最好的情况下，当 A[0] == A[1] 时，它只运行一次（自己说服自己这一点！）。在最坏的情况下， j 为 i 在外层循环中取的每个值都初始化一次，因此总共初始化了 10000 次。

随着我们进一步深入循环，计算确切次数变得越来越不可行。我们将在后面展示，确切的数字并不那么重要。

总结技术 2A，我们解决了机器独立性的问题。不同机器的差异不会影响运行操作的总数（通常）。然而，计算每种操作的计数非常繁琐。此外，我们选择的输入大小是任意的，我们不知道实际运行需要多少时间。

Asymptotic Behavior

在大多数应用中，我们最关心的是当 NN 值非常大时会发生什么。这被称为渐近行为。我们希望了解哪些类型的算法能够处理大量数据。需要高效算法的应用实例包括：

  • 模拟数十亿粒子的相互作用
  • 维护一个拥有数十亿用户的社交网络
  • 编码数十亿字节的视频数据

扩展性好的算法比扩展性差的算法具有更好的渐近运行时行为。

让我们回到最初的问题，即描述我们的 dup 函数的运行时间。回想一下，我们希望这些描述具有以下特点：

  • 简单且数学上严谨。
  • 明确展示 dup2 比 dup1 更优越。

我们已经完成了第二项任务！我们可以清楚地看到 dup2 的表现优于 dup1 。然而，我们没有以一种非常简单或数学严谨的方式完成它。幸运的是，我们可以应用一系列简化来解决这个问题。

Simplification 1: Consider Only the Worst Case

在比较算法时，我们通常只关心最坏情况。最坏情况往往能展现出最有趣的效果，因此我们通常可以忽略除最坏情况之外的所有其他情况。

Simplification 2: Restrict Attention to One Operation

选择一个代表性的操作作为整体运行时间的代理。从我们的 dup 示例：

  • 好的选择： increment ，或者小于等于，或者数组访问。
  • 不好的选择： j = i + 1 的赋值，或者 i = 0.

我们选择的操作称为“成本模型”。

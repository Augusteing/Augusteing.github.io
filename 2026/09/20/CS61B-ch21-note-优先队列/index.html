21.1 Priority Queues

#cs61b

二叉搜索树让我们能够高效地搜索树，时间复杂度仅为$$log(N)$$这是因为我们可以在搜索的每一步中排除树中一半的元素。但如果我们更关心快速找到最小或最大的元素，而不是快速搜索呢？

现在我们来介绍优先队列这一抽象数据类型。为了理解这个 ADT，想象一个装有物品的袋子。你可以往这个袋子里添加物品，也可以从中移除物品，等等。但有一个限制：你只能与这个袋子中最小的物品进行交互。

Priority Queue Implementation

我们使用优先队列 ADT 解决了同样的问题，使内存利用更高效。可以观察到代码略微复杂，但并非总是如此。

请记住，ADT 类似于接口，其具体实现仍有待定义。让我们考虑使用已知数据结构实现来构建优先队列，并分析所需操作在最坏情况下的运行时间：

  • Ordered Array
    • add: $$Θ(N)$$
    • getSmallest: $$Θ(1)$$
    • removeSmallest: $$Θ(1)$$
  • Bushy BST
    • add: $$Θ(logN)$$
    • getSmallest: $$Θ(logN)$$
    • removeSmallest: $$Θ(logN)$$
  • HashTable
    • add: $$Θ(1)$$
    • getSmallest: $$Θ(N)$$
    • removeSmallest: $$Θ(N)$$

Summary

  • 优先队列是一种抽象数据类型，它针对处理最小或最大元素进行了优化。
  • 使用这种专用数据结构可以带来空间/内存方面的优势。
  • 我们目前所知的 ADT 实现，无法为优先队列操作提供高效的运行时间。
    • 二叉搜索树是这些结构中最有效率的

21.2 Heaps

如何实现我们的优先队列呢？

我们之前看到，对于优先队列操作，已知数据结构中运行时间最优的是二叉搜索树。通过修改其结构和约束条件，我们可以进一步改善这些操作的运行时间和效率。

我们将二叉最小堆定义为完全二叉树，且满足最小堆性质：

  • 最小堆：每个节点都小于或等于其两个子节点
  • 完全性：缺失项仅出现在最底层（如果有的话），所有节点都尽可能靠左排列。

如上图所示，绿色的堆是有效的，而红色的则不是。最后两个无效是因为它们至少违反了上述定义的性质之一。

Heap Operations

对于优先队列 ADT，我们关注三个核心方法： add 、 getSmallest 和 removeSmallest 。首先从概念层面说明，如何基于给定的堆结构实现这些方法。

  • add ：暂时将元素添加到堆的末尾，然后通过上浮操作将其调整到正确位置。
    • 上浮操作会在子节点小于父节点时交换两者位置
  • getSmallest ：返回堆的根节点（根据最小堆性质，该节点必定是最小值）
  • removeSmallest ：将堆中的最后一个元素交换到根节点，然后向下沉降至合适位置。
    • 下沉操作会在父节点大于子节点时进行交换。为保持最小堆性质，需与最小的子节点交换。

Approach 2

回顾一下并查集抽象数据类型。我们表示加权快速合并结构的方式是通过数组。对于树的表示，我们可以同时存储键数组和父节点数组。键数组表示哪个索引映射到哪个键，而父节点数组则表示哪个键是另一个键的子节点。

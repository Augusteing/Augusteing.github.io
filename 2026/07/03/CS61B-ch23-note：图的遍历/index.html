BFS 和 DFS

在第 22.4 节中，我们介绍了图的深度优先搜索遍历。在深度优先搜索中，我们会沿着第一个子节点的整个谱系向下访问，然后才开始查看第二个子节点——我们确实是在优先搜索深度。

这里，我们将讨论广度优先搜索（也称为层序遍历）。在广度优先搜索中，我们会先访问所有直接子节点，然后再继续访问任何孙节点。换句话说，我们先访问距离源点 1 条边的所有节点，然后是距离源点 2 条边的所有节点，以此类推。

边缘（fringe）是我们用来存储遍历发现过程中前沿节点（即等待查看的下一个节点）的数据结构的术语。对于 BFS，我们使用队列作为边缘。

edgeTo[...] 是一个映射，帮助我们追踪如何到达节点 n ；我们是通过从 v 到 n 的边到达它的。

distTo[...] 是一个映射，帮助我们追踪 n 距离起始顶点有多远。假设每条边的距离为 1 ，那么到 n 的距离就比到 v 的距离多 1。为什么？我们可以利用已知的到达 v 的路径，然后通过 v 和 n 之间必然存在的边（它必须存在，因为在 for 循环头中， n 被定义为 v 的邻居）再付出 1 的代价来到达 n 。

DFS vs BFS

DFS 使用栈作为边缘的数据结构

但请注意，DFS 和 BFS 的区别不仅仅在于它们边缘集合的数据结构。它们标记节点的顺序也不同。对于 DFS，我们仅在访问节点时——即将其从边缘集合中弹出时——才标记节点。因此，如果某个节点已被加入队列但尚未被访问，那么栈中可能同时存在该节点的多个实例。而对于 BFS，我们一旦将节点添加到边缘集合就会立即标记它，所以这种情况不可能发生。

图的API以及图的实现

图的实现

API（应用程序编程接口）是供类的使用者调用的方法列表，包括方法签名（每个函数接受哪些参数）以及关于其行为的信息。你之前已经见过 Java 开发者为其提供的类（例如 Deque）所编写的 API。

对于我们的图 API，我们采用一种通用惯例，即为每个唯一节点分配一个整数编号。这可以通过维护一个映射来实现，该映射能告诉我们每个原始节点标签所对应的整数。这样做可以让我们定义专门处理整数的 API，而无需引入泛型类型。

既然我们知道了如何在纸上绘制图，并理解了基本概念和定义，现在就可以考虑图在计算机内部应该如何表示了。我们希望能够快速回答关于图的以下问题：

  • 给定的顶点 u 和 v 是否相邻？
  • 顶点 v 是否与特定边 e 关联？
  • 哪些顶点与 v 相邻？
  • 哪些边与 v 关联？

之所以提出这些问题，是因为他们和我们图的遍历有关。很多关于图的问题，我们需要对图或者其子图进行搜索。

The Adjacency List

在邻接表中，会创建一个与图中顶点数量大小相同的数组。数组中的每个位置代表图中的一个顶点。每个位置都指向一个列表。这些列表被称为邻接表，因为列表中的每个元素都代表该顶点的一个邻居。

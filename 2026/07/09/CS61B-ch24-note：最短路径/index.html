前瞻

我们是否开发出了一种算法，能够找到从给定顶点到所有其他可达顶点的最短路径？嗯，算是吧。我们开发出了一种在无边权标记的图上表现良好的算法。我们做了这些：开发出了一种算法，能够找到从给定源顶点出发的最短路径（这里”最短”指的是边数最少）。

但这并不总是”最短”的正确定义。有时，图的边可能带有”权重”，如果 A-B 边的权重为 5，而 A-C 边的权重仅为 3，那么 A-B 就被认为比 A-C 更远。

这就是为什么当图中存在边权重时，我们需要一种不同的算法来寻找最短路径。

缔结斯特算法（前有悲伤 所以运筹学万岁吧）

考虑以下示例。你在校园里，和朋友们在赫斯特纪念矿业大楼附近玩游戏。你从位置 s 出发，想要到达位置 t 。

BFS 会生成一条长度为 330 米的路线，而不是最短路径，因此我们需要一种考虑边距离（也称为”边权重”）的算法。

观察

请注意，最短路径（对于边带权重的图）可能包含很多很多条边。我们想要最小化的是所选路径上各边权重之和。

其次，注意从源点 s 出发的最短路径树可以通过以下方式构建：

  • 对于图中每个顶点 v （不包括 s ），找出从 s 到 v 的最短路径。
  • 将你找到的所有边”组合”/“合并”起来。大功告成！

最终我们会得到一个“树”，因为对于一个节点到其他节点的最短路径，如果路径中存在环，由于边是非负的，我们只是在徒增距离而已，所以对于这种路径，不存在环。

我们将这种树称为最短路径树，如果节点的数量为 V，那么该树的边数量为V-1

bad Algorithm

这种改进版的BFS是有效的，但是内存上和时间上效率很低。试想我们有一个长度为1500000的边，难道我们要创建这么多的虚拟节点吗？

贪心算法对于这个问题效果不佳，如果我们一开始选择 A->B 作为最短路径，我们就会错过 A -> C -> B 的这一条更短的路径。所以说我们需要对我们的选择进行更新。

Dijkstra’s Algorithm

Dijkstra 算法接收一个输入顶点 s，并输出从 s 出发的最短路径树。它是如何工作的呢？

  1. 初始化 (Initialization):

    • 将所有节点的 distTo 设为 $\infty$ (无穷大)。

    • 将起点的 distTo[s] 设为 $0$。

    • 将所有节点加入优先队列 PQ 中，优先级为其 distTo 的值。

  2. 提取最小节点 (Dequeue Min):

    • 只要优先队列不为空，就弹出 (Pop/removeMin) 优先级最高（即 distTo 最小）的节点，我们称之为当前节点 $u$。

    • 注意：一旦节点从 PQ 中弹出，意味着从起点 $s$ 到节点 $u$ 的最短路径已经永久确定，后续不会再改变。

  3. 松弛邻居 (Edge Relaxation):

    • 遍历当前节点 $u$ 的所有相邻且仍在 PQ 中的邻居节点 $v$。

    • 计算可能的更短路径：potentialDist = distTo[u] + weight(u, v)

    • 如果 potentialDist < distTo[v]：

      • 更新距离：distTo[v] = potentialDist

      • 记录路径：edgeTo[v] = u (核心！这是构建树的关键)

      • 更新优先级：在 PQ 中更新节点 $v$ 的优先级为 potentialDist (调用 changePriority 操作)。

  4. 循环重复:

    • 不断重复步骤 2 和 3，直到 PQ 为空，或到达目标节点（如果只求两点间最短路）。

只要所有边的权重均为非负值，Dijkstra 算法就能保证找到最优解。

引理一：对于即将要被处理的节点 v，我们确定dist[s, v] 已经是最优的距离。

证明：对于弹出来的节点，根据优先队列的定义，是目前已知的距离顶点 s 最近的节点。

假设存在另外一条路径 s - v1 - … - v 使得到 v 的路径比现已经知道的更短。那么由于非负边的特性，s - v1 的距离一定小于到 v 的距离。

这里出现了矛盾，因为我们要处理的是 v 而不是 v1。

或许你会说 v1 万一已经处理过了呢？

根据我们算法的定义，如果 v1已经处理过了那么 v 的最优路径会被更新为 s - v1 - .. -v，我们上述的讨论也就不成立，所以 v1 必定没有被处理过。

根据引理一，这样我们继续处理所有的节点 v，就能得到顶点 s 到所有节点的最短距离。

负向边

当负边出现时，情况可能会变得非常糟糕。请看下图。

假设你位于标记为 34 的顶点。现在你要尝试松弛所有边。你只有一条从自身指向 33 的出边，权重为 −67。啊，但请注意：顶点 33 已经被访问过（它被标记为白色）。所以……我们不松弛它。（回想一下 relax 方法的伪代码。）

现在我们回到家，认为到 33 的最短距离是 82（用粉色标记）。但实际上，我们应该走经过 34 的路径，因为那样会得到 101−67=34 的距离。哎呀。

Dijkstra 算法在处理负权边时无法保证正确性。它可能有效……但并非绝对可靠。

一个值得注意的不变量

注意，一旦某个顶点从优先队列中弹出，它就永远不会被重新加入，其距离值也永远不会被更新。换句话说，当顶点从优先队列中弹出时，我们就已经确定了从源点到该顶点的真实最短距离。

这一事实的一个好处是”短路”特性。假设……我不关心最短路径树，只想找到从某个源点到某个目标点的最短路径。比如，你想把世界上的城市放在一张图上，找到从伯克利到奥克兰的最短路径。运行 dijkstra(Berkeley) 意味着你无法真正停下这个强大的算法猛兽……你必须让它一直运行……直到它找到通往洛杉矶、休斯顿、纽约市以及所有可能地方的最短路径！

好的。一旦在算法中从优先队列弹出 Oakland ，我们就可以直接停止。此时只需返回已有的距离和路径，结果就是正确的。因此，有时 dijkstra 不仅接收源点，还接收目标点，目的就是为了实现短路操作。

效率

A*

在 Dijkstra 算法一节的末尾，我们讨论了一种可能的改进方法：让 Dijkstra 算法在找到目标节点时立即终止搜索。这种方法是否足够好？

要回答上述问题，我们需要深入思考 Dijkstra 算法的实际工作原理。从图形上看，Dijkstra 算法从源节点开始（想象源节点是圆心），然后以该点为中心生成同心圆，半径逐渐增大，并”扫过”这些圆，捕获其中的节点。

因此… Dijkstra 算法首先访问距离源节点最近的城市，然后是次近的城市，接着是第三近的城市，依此类推。这听起来是个好主意。Dijkstra 算法实际上是在按距离递增的顺序访问节点：先访问所有距离为 1 单位的城市，然后是距离为 2 单位的城市，以此类推，就像同心圆一样。

现在想象一下：在美国地图上，从中心附近的某个地方开始，比如丹佛。现在，我想让你用 Dijkstra 算法帮我找到一条通往纽约的路径。你最终会按照”最近同心圆”的顺序遍历节点。

你会先画一个小圆，就在丹佛周围，访问那个圆内的所有城市。最终，你的圆会变得越来越大，你会画出一个经过拉斯维加斯的圆（并且到那时，你已经访问了圆内所有其他城市）。然后，你的圆会大到足以吞没洛杉矶和达拉斯……但你离纽约还远着呢。所有这些努力，所有这些圆，但仍然……离目标如此遥远。提前终止（Short-circuiting）有所帮助，但前提是你真的能快速命中目标节点。

要是存在一种方法，能利用你的先验知识——即纽约在东边，这样你就可以”提示”你的算法优先选择东边的节点，而不是西边的节点，那该多好。

A

不，不是天上的星星。这是一种叫 A*的算法。

观察以下现象：Dijkstra 算法给出的是从起点到某个节点的”真实”距离（即非估计值）。比如说，你从丹佛出发，访问了伊利诺伊州的一个城市，此时你就有了到丹佛的真实距离。但我们缺少的是：从某个节点到目标节点纽约的某种粗略估计值。有了这个，拼图就完整了。因为这样一来，把这两者相加（从起点到节点的真实距离 + 从节点到目标的估计距离），就能得到从起点到目标的估计距离。当然，从节点到目标的原始估计越准确，从起点到目标的估计就越准确，A*算法的运行效果也就越好。

因此，我们对 Dijkstra 算法稍作修改。在 Dijkstra 算法中，我们使用 bestKnownDistToV 作为优先级。这次，我们将使用 bestKnownDistToV + estimateFromVToGoal 作为启发式函数。

先有鸡还是先有蛋

我们遇到了一个问题。我们如何知道这个估计值是多少？我的意思是，这个估计值本身就是一个距离，而我们正在使用 A* 算法来寻找某个节点到另一个节点的距离。

我们似乎遇到了经典的”先有鸡还是先有蛋”问题。”先有鸡，还是先有蛋？”顺便说一句，Reddit 上有个用户对此提出了一个想法。

之所以称之为估计值，正是因为它本身就是一种近似。我们使用 A* 算法来寻找从起点到终点的真实最短路径，但估计值是我们近似得出的。有时想出好的估计值相当困难。

不过，以丹佛到纽约的例子来说明。我们可以直接查找这些城市的 GPS 坐标，然后通过某种方式计算它们之间的直线距离。当然，这并不准确，因为从丹佛到纽约可能根本不存在一条可以通行的直线路径，但这仍然是一个相当不错的估计！

糟糕的启发式函数

假设从丹佛到纽约的最短路径会经过某个城市 C 。再假设我的 GPS 坏了，导致我认为这个城市 C 与其他所有地方的距离都是无穷远，于是我将图中其他所有节点到 C 的估计距离都设为了∞。

会发生什么？A* 算法基本上永远不会想要访问这个城市。（回想一下优先队列中的优先级是如何确定的；对于这个城市，即使我访问了它的直接邻居，它的优先级也始终是∞。毕竟，从它的直接邻居到这个城市的估计距离都被设为了∞。）

那么……现在怎么办？我们失败了。A* 算法失效了。我们得到了错误的答案。糟糕。

这里的要点是，启发式函数必须是好的。关于“好”的定义，有两个必要条件。

可采纳性：heuristic(v, target) ≤ trueDistance(v, target)。（思考上述问题。从 C 的邻居到 C的真实距离并非无穷大，而是小得多。但我们的启发式函数却声称它是 ∞，因此违反了这条规则。）

一致性：对于 w 的每个邻居 v ：

  • heuristic(v, target) ≤ dist(v, w) + heuristic(w, target)
  • 其中 dist(v, w) 是从 v 到 w 的边的权重。

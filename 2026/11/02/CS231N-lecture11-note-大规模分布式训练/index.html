CS231N lecture11 note 大规模分布式训练

GPU

GPU 全称为 Graphic Processing Unit，本质上是处理图像计算的硬件，具有很好的并行计算的能力。Nvidia 早在 10s 就开始投入并行计算这一领域，为深度学习提供了硬件基础。

H100的机构

H100 应该是25年左右单卡性能最好的 GPU, AMD 和 谷歌也有类似的深度学习计算单元。

由 132 个流式处理器和中心的L2内存构成（实际上一个 H100 的计算核心有 144 个核心，但是 NVidia 只承诺 132 个是可用的。

我猜测是工程上的原因。

显卡集群

llmma 3 训练集群由接近 25000 块 GPU 构成。
说实话按照之前 GPT 员工的说法，似乎十万+ 的集群也属于正常。

可以近似的将模型看作一个大电脑，在这个超级强力的电脑中就可以完成计算。

训练算法

数据并行算法过程如上，首先每块 GPU 都有模型的全部权重和优化器（Adam），每块 GPU 处理自己的小批次数据，之后再进行前向传播，反向传播，最后平均梯度到所有的GPU，每个GPU更新自己的梯度。

其中计算反向传播和更新平均梯度可以并行。

这样做的一个问题就是，每个模型要存模型的全部权重，会将模型的大小限制在 1B 左右。

FSPD

快速 DP的基本思想是：不同 GPU 各司其职，只负责某一层的向前和后向传播，在其他 GPU 需要自己的层的时候，就互相通信，之后不负责该层的 GPU 删除权重腾出内存，反向传播时同理，最后更新了权重也广播到所有的 GPU。

激活值检查


反向传播的过程需要利用激活值，但是大量激活值的存储也是不可接受的，于是我们提出了重算激活值的方法，在反向传播需要时才计算该层的激活值，但是这会导致时间大大延长，所以我们设置几个点，每隔几层保存一些激活值，这些都是很朴素的思想。

HFU和MFU

HFU 的定义是指 GPU 在模型上花费的算力/ GPU 的理论总算力。

但是 GPU 不仅仅只能做计算对吧，还有很多事情可以完成，所以：MFU 被定义了

MFU 衡量的是：模型完成有效训练任务所需的 FLOPs，占硬件理论峰值 FLOPs 的比例。

上下文并行


将数据沿着序列维度切分，GPU 1 和 GPU 2 负责处理同一个 token 的不同内容。

流水线并行

模型不同的层由不同的 GPU 负责，但是这样做的坏处就是高度的串行了，所以我们将数据处理为多个批次，如图处理为 4 个批次。

这也是很朴素的想法。

张量并行

某些大张量可以被切分为多个小张量，分在不同的 GPU 上进行计算。

summary

  • GPU 确实是近 10 年以来进步最快的基础设备之一，提高了近 1000 倍的算力
  • 现在的大语言模型都在万卡甚至十万卡的设备上运行，搞ai确实费钱
  • 为了大规模的分布式运行，我们需要设计很多算法。
  • 总的来说是希望 MFU 的指标越来越好，根据 DeepSeek和llmma开源的细节，大部分的 MFU 都在 30 - 50% 的区间。

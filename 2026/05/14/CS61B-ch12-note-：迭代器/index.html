Exceptions

这个解决方案虽然看似简单优雅，但实际上不够效率(原文这里用的是naive,翻译为天真总觉得有讽喻之意）。这是因为当你在 Java 中使用字符串连接操作时，例如： returnString += keys[i]; ，你实际上并不是仅仅在 returnString 后面追加内容，而是在创建一个全新的字符串。这是非常低效的，因为创建一个新的字符串对象也需要时间！具体来说，创建新字符串的时间与字符串的长度呈线性关系（我们将在后面的章节中讨论为什么会这样！）。

加分题：假设将一个字符连接到字符串需要 1 秒钟。如果我们有一个大小为 5 的 ArraySet： {1, 2, 3, 4, 5} ，运行 toString() 方法需要多长时间？

答案：我们将 returnString 设置为左括号，这需要 1 秒钟，因为这涉及到将 { 添加到空字符串 "" 中。添加第一个元素将涉及创建一个全新的字符串，添加}和 1，这将花费 2 秒钟。添加第二个元素需要 3 秒钟，因为我们需要添加 { 、 1 、 2 。这个过程会持续进行，因此对于整个数组集，总时间是 1 + 2 + 3 + 4 + 5 + 6 + 7.

为了解决这个问题，Java 有一个特殊的类叫做 StringBuilder 。它创建一个可变的字符串对象，所以你可以继续向同一个字符串对象追加，而不是每次都创建一个新的对象。

Java 中 equals 方法的规则：重写 .equals() 方法有时可能比看起来更棘手。在实现你的 .equals() 方法时，应遵循以下规则：

  • equals 必须是等价关系
  • 自反性： x.equals(x) 为真
  • 对称性： x.equals(y) 当且仅当 y.equals(x)
  • 传递性： x.equals(y) 和 y.equals(z) 蕴含 x.equals(z)
  • 它必须接受一个 Object 类型的参数，以便覆盖原始的 .equals() 方法
  • 它必须保持一致性，如果 x.equals(y) ，只要 x 和 y 不变： x 必须继续等于 y
  • 对于 null 永远不为真， x.equals(null) 必须是 false

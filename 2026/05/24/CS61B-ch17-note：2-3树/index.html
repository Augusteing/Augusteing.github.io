Tree Height

BST（二叉搜索树）的一个不幸特征是，它们的形态介于最好的情况“茂密 (bushy)”树和最坏的情况“细长 (spindly)”树之间。

在最好的情况下，树的高度为 $\Theta(\log N)$；而在最坏的情况下，树的高度为 $\Theta(N)$，此时它基本上变成了链表。例如，在“细长”的 BST 上执行 contains 操作将花费线性时间。

下方的两棵树高度均为 $H = 3$，然而左边的树比右边的树能容纳更多的项。

  • 左侧（茂密）：$H = \Theta(\log N)$

  • 右侧（细长）：$H = \Theta(N)$

17.2 Big O 与 最坏情况 (Big O vs. Worst Case)

关于渐进分析的一段小插曲

考虑以下关于 BST（二叉搜索树）的陈述。哪些是正确的？

  1. BST 的最坏情况高度是 $\Theta(N)$。

  2. BST 的高度是 $O(N)$。

  3. BST 的高度是 $O(N^2)$。

答案是这三个陈述都是正确的。BST 总是具有线性或更优的高度，而线性高度显然“小于”最后一点提到的二次上界。

然而，一个更棘手的问题是，这三个陈述中哪一个信息量最大。

这里的答案是第一个陈述：与其他陈述不同，它给出了精确的上界和下界。$O(N)$ 可能意味着线性、对数、平方根或常数，但 $\Theta(N)$ 只能意味着线性。

打个比方，考虑以下关于酒店房间最坏情况费用的陈述：

  1. 最贵的房间是 $639/晚。

  2. 最贵的房间小于或等于 $2000/晚。

在这里，我们看到第一个陈述给了我们确切的信息，而第二个陈述则没有。在第二个陈述中，最贵的房间可能是 $2000、$10 或介于两者之间的任何价格。

然而，_两者都是关于最坏情况的陈述_。将其应用于渐进符号，这意味着我们可以用 $\Theta$、$O$ 甚至 $\Omega$ 来指代最坏情况。Big O 与最坏情况并不相同！

我知道我们的教学中，很多情况下大家对一个算法都说 O（f（n））意思是这个算法的最坏情况下的时间复杂度。但是实际上O只是一个上界而已，O(n^2)在数学上来说

使用 Big O (Using Big O)

如果 $\Theta$ 总是比 $O$ 信息量更大，那我们为什么还要费心使用 Big O 符号呢？有几个原因：

  • 我们可以做出更宽泛的陈述。例如，说“二分查找是 $O(\log N)$”是正确的，但说“二分查找树是 $\Theta(\log N)$”则是不正确的，因为它在某些场景下可能是常数。

  • 有时，确定精确的运行时间是不可能的或极其困难的。在这种情况下，我们仍然希望提供一个广义的上界。

17.3 B-树操作 (B-Tree Operations)

高度与深度 (Height and Depth)

BST 的平均高度和深度是决定性能的重要属性。高度 (Height) 指的是最深叶子节点的深度，它是一个整棵树的属性；而 深度 (depth) 指的是特定节点距离根节点的距离，它是特定于节点的属性。

树的 平均深度 (average depth) 是所有节点深度的平均值。

! (图注：二叉树的高度和深度。图中展示了一棵高度为 4 的树，根节点 k 位于深度 0，最深的叶子节点 s 位于深度 4)

这个图中的例子中，树的平均深度为2.35，这说明了当我们随机搜索一个数的时候，我们所需要耗费的时间大约为2.35个单位。

BSTs 在实践中的应用

树的高度和平均深度决定了 BST 操作的运行时间。高度决定了查找节点的最坏情况运行时间，而平均深度决定了搜索操作的平均情况运行时间。

我们插入节点的顺序对 BST 的高度和平均深度有重大影响。例如，考虑插入节点 1, 2, 3, 4, 5, 6, 7 。这会导致一个细长的 BST，高度为 6，平均深度为 3。如果我们以顺序 4, 2, 1, 3, 6, 5, 7 插入相同的节点，我们会得到一个更好的高度为 2 和平均深度为 1.43。

所以说随即插入是非常有用的！

现实世界中的 BST (Real-World BSTs)

在思考 BST（二叉搜索树）如何在现实应用中运作时，我们可以先从随机化 BST 开始考虑。

幸运的是，平均而言，随机生成的插入顺序具有 $\log N$ 的高度和平均深度。事实上，可以证明平均点的深度为 $E[d] = 2 \ln N$ 且平均树的高度为 $E[h] = 4.311 \ln N$（该证明超出了本课程的范围）。即使同时考虑插入和删除，这些属性仍然成立。

很遗憾的是，并不总是能够随机化插入顺序。例如，如果我们有按顺序传入的实时数据，由于我们无法一次性获得所有数据点，因此无法打乱数据。随机插入了。

因此，我们需要一种不同的方法来保持搜索树的“茂密性 (bushiness)”。

B-树 (B-Trees)

避免不平衡 (Avoiding Imbalance)

如果我们能简单地避免在 BST（二叉搜索树）中添加新的叶子节点，树的高度就永远不会增加。然而，这种想法是不可行的，因为我们终究需要在某个时刻插入值。

我们可能采用的一个想法是“过度填充 (overstuffing)”叶子节点。我们不再在插入时添加新节点，而是简单地将新值堆叠到现有叶子节点的适当位置。

! (图注：在执行 insert(17) 时对节点进行过度填充)

这种做法存在一个明显的缺陷：叶子节点会变得过于庞大，本质上退化成了线性列表，导致查找操作又回到了低效的线性查找。为了解决这个问题，当叶子节点内的元素达到一定数量时，我们可以考虑将其中的一个值“向上移动”（moving up）到它的父节点中。

Moving Items Up

为了改善叶子节点过度填充的问题，我们可以在叶子节点达到一定数量的值时考虑将一个值”向上移动”。

然而，直接向上移动可能会破坏二叉搜索树的性质（例如导致原本比它小的元素跑到了它的右侧）。上图中的17跑到了和15一处节点，但是破坏了搜索二叉树的性质。
为此我们需要进行第二次修复：将过度填充节点的子节点拆分成多个范围区间。例如，将范围拆分为 (−∞,15)、 和 (18,∞)。在这种结构下，查找操作依然和常规的 BST 一样，只是当寻找 15 到 17 之间的值时，我们会进入中间的子分支，而不是单纯的左分支或右分支。

在上图中，我们将一个过载节点的子节点分成范围： (−∞,15)， [15,17]，和 (18,∞) 。在这个结构上的搜索将和 BST 完全相同，除了在 15 和 17 之间的值，我们会去中间子节点而不是左子节点或右子节点。

如果我们设置某个常数 $L$ 作为节点大小的限制，我们的搜索时间只增加一个常数因子（换句话说，没有渐近变化）。

向节点添加元素可能会引发级联的连锁反应，如下面的图片所示，我们在其中添加了 25 和 26 。

Splitting the root  分裂根节点

Perfect Balance

注意到我们新的分裂树数据结构具有完美的平衡性。

如果我们分裂根节点，每个节点都会下移一层。如果我们分裂一个叶子节点或内部节点，高度不会改变。永远不会发生导致不平衡的变化。

这种数据结构的真正名称是 B 树。每个节点最多包含 3 个元素的 B 树也被称为 2-3-4 树或 2-4 树（一个节点可以有 2、3 或 4 个子节点）。将每个节点限制为最多包含 2 个元素，就会得到一个 2-3 树。

B-Tree Usage

B 树主要在两个特定场景中使用：首先，用一个小 L 来在概念上平衡搜索树；其次，用 L 在千级来处理具有大量记录的数据库和文件系统。

B 树的不变性

由于 B 树的构建方式，它们具有两个不变性：

  • 所有叶子节点与根节点的距离相同。（因为是平衡的）
  • 一个含有 k 个元素的非叶子节点必须恰好有 k+1 个子节点。

以上两个不变性保证了 B 树的$logN$ 高度

B-Tree Performance

运行时分析

要考虑 B 树的运行时间，设 $L$ 为每个节点的最大项数。根据我们的不变量，最大高度必须在 $log_{⁡L+1}N$（最好情况，所有节点都有 L项）和 $log_⁡2N$ （最坏情况，每个节点只有 1 项）之间。
因此，整体高度总是在 $Θ(log⁡N)$ 的数量级上

Runtime for contains

对于 contains 这种操作，我们需要考虑以下的最坏情况。

最坏情况下，每一个节点都存在着 $L$ 个元素，对于每一个节点，都需要 $L$ 次线性查找的时间。同时，对于整个树，我们有 $log_{L+1}N$ 的深度。所以对于 contanis 操作来说，需要 $\theta (LlogN)$ 的时间复杂度。

Runtime for add

对于 add 操作，我们需要考虑一下最坏的情况：

就是从根节点到叶子节点我们都需要进行拆分：这样会加入一个$logN$ 的线性操作时间，加上我们需要从根节点走到叶子节点，所以也需要 $logN$ 的操作。所以对于ADD操作，我们需要$\theta(logN)$ 的操作时间。

总结

  • BSTs 具有最佳情况下的高度 $Θ(log⁡N)$，以及最坏情况下的高度 $Θ(N)$
  • 大 O 不是最坏情况！（但我们经常这么理解）
  • B 树是对 BST 的一种改进，它们在最坏情况下保持 $Θ(log⁡N)$ 的运行时间对于 add 和 contains 。它们在插入过程中保持完美平衡。
  • B 树对节点可以持有的值的数量有一个限制 L ，而不是像 BST 那样每个节点只有一个项目。
  • 在 B-Tree 中插入 add 时，我们只需将值追加到正确位置的现有叶节点中，而不是创建新的叶节点。如果节点过于满，它会分裂并将一个值向上推送。

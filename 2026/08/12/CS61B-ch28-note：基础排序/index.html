排序的定义

对于一组元素，如果能够排序应该满足如下的性质：

  • 元素可以被比较， 元素 a 和 b 共有三种关系 a > b, a = b, b > a
  • 具有传递性 a < b b < c -> a < c

我们有许多种排序的方式，不只局限于数字的大小。

比如：在对字符串进行排序的时候，我们可能会采用以下的排列方式：

  • 字符串的长度
  • ASCII码的顺序
  • 首字母的顺序（实际上这回和ASCII码出现同样的顺序）

时间复杂度和空间复杂度

我们之前讨论的渐进分析实际上就基于此，时间复杂度可以被理解为之前的运行时分析。

空间复杂度是指运行算法时所需要占据的空间，比如迪杰斯特拉算法需要优先队列存储所有的节点，需要O(V) 的内存。

值得一提的是，递归算法需要的空间复杂度基本和递归调用的次数成正比。

比如计算斐波那契数列如果你只使用递归调用的话，在计算相当大的数字时，需要的空间也会几何增长。

选择排序

  • 从序列中找到最小的数，放置到队首
  • 对于剩下的序列重新寻找最小的数。

运行时分析 $\theta(n^2)$ 占用内存为 $\theta(1)$ （因为我们考虑的是额外的内存，接受输入不算）

选择排序的改进

如果我们使用最大堆或者最小堆来查找呢？

我们创建一个最大堆（堆的最大项目在首部），先将所有元素插入最大堆，然后依次取出最大的元素放入输出的队尾（我们假设想让元素从小到大排列）

这个算法的时间复杂度为 $O(nlogn)$


现代算法之所以更重视时间复杂度，更多的是因为截止到2026年，我们已经存在了PB级的数据存储，但是很遗憾的是一天仍然只有24个小时。


针对这个算法，有办法使得空间复杂度降到常数级

自底而上成堆和自顶而下成堆的最好情况下算法复杂度不同，自底而上成堆为 O（n),对比自顶而下为 O(nlogn)

Abstract Data Types

还记得我们之前说的吗？

抽象数据类型（ADT）仅由其操作定义，而非其实现。

例如在项目 1A 中，我们开发了一个 ArrayDeque 和一个 LinkedListDeque ，它们具有相同的方法，但方法的编写方式差异很大。在这种情况下，我们称 ArrayDeque 和 LinkedListDeque 是 Deque ADT 的实现。

从这种描述中，我们看到 ADT 和接口有一定的关联。概念上， Deque 是一个接口，而 ArrayDeque 和 LinkedListDeque 是其实现。在代码中，为了表达这种关系，我们有 ArrayDeque 和 LinkedListDeque 类继承自 Deque 接口。

一些常用的 ADT 包括：

  • 栈：支持元素后进先出检索的结构（后进先出）

  • push(int x) : 将 x 放在栈顶

  • int pop() : 取出栈顶元素

  • 列表：一组有序元素

  • add(int i) : 添加一个元素

  • int get(int i) : 获取索引为 i 的元素

  • 集合：一组无序的唯一元素（不重复）

  • add(int i) : 添加一个元素

  • contains(int i) : 返回一个布尔值，表示集合是否包含该值

  • 映射(map)：键值对集合

  • put(K key, V value) : 将键值对放入映射中

  • V get(K key) : 获取与键对应的值

以上接口都是一个更大的接口的的子接口 该接口称为 Collections.

下面我们展示了接口和类之间的关系。接口以白色显示，类以蓝色显示。

ADT 使我们能够以高效和优雅的方式使用面向对象编程。例如，你在项目 1C 中看到，你可以互换地使用 ArrayDeque 或 LinkedListArrayDeque，因为它们都属于 Deque ADT 的一部分。

在接下来的章节中，我们将致力于定义一些更多的抽象数据类型（ADT），并列举它们的不同的实现方式。

那我们该如何制作MAP 或者 Set？

Binary Search Trees

链表很棒，但即使列表已排序，查找一个元素也需要很长时间！如果元素在列表的末尾呢？那将需要线性时间！

我们知道对于数组，我们可以使用二分查找来更快地找到一个元素。具体来说，可以在 log⁡n时间内完成。关于二分查找的简要解释，可以查看这个链接。

在二分查找中，我们知道列表已排序，所以我们可以利用这些信息来缩小搜索范围。首先，我们查看中间元素。如果它比我们要查找的元素大，我们就查看它的左侧。如果它比我们要查找的元素小，我们就查看它的右侧。然后，我们查看相应两半的中间元素并重复这个过程，直到找到我们要查找的元素（或者因为列表不包含它而找不到）。

但我们如何对链表进行二分查找呢？我们必须一直遍历到中间位置才能检查那里的元素，这本身就需要线性时间！

我们可以实现的一种优化是保留一个指向中间节点的引用。这样我们就能在常数时间内到达中间节点。然后，如果我们翻转节点的指针，这使我们能够遍历左右两半，我们就能将运行时间减少一半！

约束：任意两个节点之间只有一条路径。

在某些树中，我们选择一个根节点，它是没有父节点的节点。

树还有叶子，叶子是没有任何子节点的节点。

  • 左子树中的每个键都小于 X 的键。
  • 右子树中的每个键都大于 X 的键。请记住这个特性！！在本模块及 61B 的整个学习过程中，我们将多次引用它。

BST Operations

Search  搜索

为了查找某个元素，我们采用二分搜索，这得益于二叉搜索树（BST）的性质。

我们知道二叉搜索树的结构是，节点右侧的所有元素都大于该节点，左侧的所有元素都小于该节点。根据这一性质，我们可以从根节点开始，将其与我们要查找的元素 X 进行比较。如果 X 大于根节点，我们就移动到根节点的右子节点。如果 X 小于根节点，我们就移动到根节点的左子节点。我们递归地重复这个过程，直到找到该元素，或者到达一个叶节点，此时说明树中不包含该元素。

如果我们的树相对“茂密”，查找操作将运行在 log⁡nlogn 时间复杂度，因为树的高度是 log⁡nlogn 。

Insert  插入

我们总是在叶节点处插入！

首先，我们在树中搜索该节点。如果我们找到了它，那么我们就不做任何操作。如果我们没有找到它，我们就已经在叶节点处了。此时，我们只需将新元素添加到叶节点的左侧或右侧，以保持二叉搜索树（BST）的性质。

Delete  删除

从二叉树中删除元素稍微复杂一些，因为每次删除时，我们需要确保重建树并仍然保持其 BST 性质。让我们将这个问题分解为三个类别：

  • 我们试图删除的节点没有子节点
  • 有一个子节点
  • 有两个子节点

Deletion: No Children

如果节点没有子节点，它就是叶节点，我们可以直接删除它的父节点指针，节点最终会被垃圾收集器清除。

Deletion: One Child  删除：一个子节点

如果一个节点只有一个子节点，我们可以确定：该子节点与该节点的父节点之间仍然满足二叉搜索树（BST）的性质，因为 BST 的性质是对左右子树递归成立的。
因此，我们只需要把父节点中原本指向该节点的子指针，重新指向这个节点的子节点即可；这样一来，该节点就不再被任何节点引用，最终会被垃圾回收机制回收。

在 BST 中删除一个只有一个子节点的节点时，可以直接让其父节点指向该子节点。由于 BST 性质对左右子树递归成立，这种替换不会破坏搜索树结构，而被删除节点会因失去引用而被垃圾回收。

（请注意，对于任意一个存在于二叉搜索树中的节点，其左（右）子节点及其子子节点都满足小于（大于）X的特性）

Deletion: Two Children  删除：两个子节点

如果节点有两个子节点，过程会变得稍微复杂一些，因为我们不能简单地指定其中一个子节点作为新的根节点。这可能会破坏 BST 属性。

相反，我们选择一个新的节点来替换被删除的节点。

我们知道新节点必须：

  • 比左子树中的任何元素都大。
  • 比右子树中的任何元素都小。

在下面的树中，我们展示了在尝试删除 dog 节点时，哪些节点会满足这些要求。

要找到这些节点，你可以直接取左子树中最右边的节点或右子树中最左边的节点。然后，我们将 dog 节点替换为 cat 或 elf ，接着删除旧的 cat 或 elf 节点。

这被称为希巴德删除法，它在删除过程中壮丽地保持了二叉搜索树性质。

BSTs as Sets and Maps

我们可以使用二叉搜索树来实现 Set 抽象数据类型。如果我们使用二叉搜索树，由于二叉搜索树的特性，我们可以将 contains 的运行时间减少到 log⁡(n) ，因为我们可以使用二分搜索！

我们还可以通过让每个二叉搜索树节点持有 (key,value) 对值而不是单个值，将二叉树转换成映射。我们将按顺序比较每个元素的键，以确定它在树中的位置。

Summary

抽象数据类型（ADT）是根据操作来定义的，而不是根据实现。一些有用的 ADT：

  • 不相交集合、映射、集合、列表。
  • Java 提供了映射、集合、列表接口，以及多种实现。

我们已经看到了两种实现集合（或映射）的方法：

  • ArraySet: 最坏情况下为Θ(N)操作。
  • BST: 如果树是平衡的，操作为Θ(logN)。

BST Implementations:  BST 实现：

  • 搜索和插入操作很简单（但插入稍微有点复杂）。
  • 删除操作更具挑战性。典型方法是“希巴德删除”。

  3. 有效且好 (valid and good)

(b) 对于以下每个问题，请回答：总是 (Always)、有时 (Sometimes) 或 **从不 (Never)**。

  1. 如果你能够修改一个已经插入到 HashMap 中的键 (key)，你稍后还能再次检索到该条目吗？例如，假设你正在将学号映射到学生姓名，并且执行了 put(303, "Elisa") 操作。现在，假设我们以某种方式找到了 HashMap 中的那个项目，并手动将键 (key) 更改为 304。如果我们稍后执行 get(304)，我们能找到并返回 “Elisa” 吗？请解释。

    我们不能找到，因为我们手动将303改到304，那么其对应的hash码应该会变化，分到的桶也会变化，我们在get（304）的时候只会往304的桶去找了

  2. 当你修改一个已经插入到 HashMap 中的值 (value) 时，你能再次检索到该条目吗？例如，在上述场景中，假设我们首先执行了 put(303, "Elisa")，然后将该项目的值 (value) 从 “Elisa” 更改为 “Daniel”。如果我们稍后执行 get(303)，我们能找到并返回 “Daniel” 吗？请解释。
    我们当然可以找到，因为我们是根据key来找值，因为key没有改变，所以对于值没有影响。

3. 薯饼配菜 (A Side of Hash Browns)

(注：标题是一个双关语，Hash 既指哈希结构，Hash Browns 是指炸薯饼)

我们想要将食物的名称映射到它们的美味程度 (yumminess)。我们希望能够在常数时间 (constant time) 内找到这些信息，所以我们决定使用 Java 内置的 HashMap 类！在这里，键 (key) 是代表食物的 String，值 (value) 是一个表示美味评分的 int。

为了简单起见，我们假设在这里一个字符串的 hashcode 就是它首字母在字母表中的位置（A=0, B=1… Z=25）。例如，字符串 “Hashbrowns” 以 “H” 开头，而 “H” 是字母表中的第 7 个字母（从 0 开始索引），因此其 hashCode 将是 7。请注意，在现实编程中，String 的 hashCode 实现要比这复杂得多。

我们的 HashMap 将通过 键的 hashcode 值除以 HashMap 中桶 (buckets) 的数量取余数 (modulo) 来计算索引 (index)。 假设初始大小为 4 个桶，并且一旦负载因子 (load factor) 达到 3/4，我们就会将 HashMap 的大小翻倍。如果我们尝试放入一个重复的键，只需将与该键关联的值替换为新值即可。
